# Интерфейс Asset Composer: реализация и проверка

Дата проверки: 9 октября 2026 года.

## Навигация и данные

Главная предлагает четыре направления. Создание предметов, окружения и рисунков не требует персонажа. Готовые примеры открываются отдельным действием. Библиотека объединяет собственные объекты и готовый каталог; связанные рисунки частей и созданные для рисунков сущности скелета не дублируются отдельными карточками.

`AssetRef` и реестр `ASSET_ACTIONS` находятся в `src/lib/assetCatalog.ts`. Общий переход `openAsset` синхронизирует объект, документ, клип, время и свойства. Интерфейсные режимы и контекст хранятся отдельно в `src/store/workbench.ts`. Переключение разделов не создаёт команды истории.

Формат `Project` и миграции сохранены. Движки сцены, совместимости, деформации и расчёта анимации продолжают использоваться существующими инструментами. Подробные инструменты контуров доступны из «Рисунок» → «Векторные контуры», возврат — «← К рисунку и слоям».

Скелет окружения создаётся независимо от выбранного персонажа. Исходная геометрия кости и анимационная поза разделены. «Параметры клипа» раскрывает расширенные настройки. Граф подписан «Просмотр состояний» и остаётся доступным только для просмотра.

## Сохранение, импорт и экспорт

Состояние сохранения отражает завершение асинхронной записи. Локальная копия и переносимый файл/папка показаны отдельно. Более старая завершившаяся запись не подменяет новую локальную ревизию. Ошибка записи позволяет повторить действие или скачать JSON.

Импорт поддерживает новый самостоятельный рисунок, слой текущего документа и подложку. Некорректный SVG оставляет окно открытым с объяснением и повторным выбором файла.

Экспорт использует собственную сущность рисунка со скелетом либо персонажа с экипировкой. Название цели показано в диалоге. Результат можно скачать повторно. Подготовка сцен и растеризация выполняются небольшими порциями, чтобы работала отмена. Каждый запуск имеет отдельный номер: результат отменённой операции не может завершить следующую операцию.

## Справка

Единый источник — `src/data/helpContent.ts`, устойчивые идентификаторы разделов, контекстный F1, поиск и FAQ. Руководство и FAQ в Markdown создаются командой `docs:help` из того же источника.

## Проверки

Общий прогон: **375 тестов прошли, 5 пропущены**, 64 файла с успешными тестами и один пропущенный файл. Использованы `--maxWorkers=2 --testTimeout=30000`. Отдельно повторены 25 проверок экспорта, контуров, навигации и сохранения. Типизация и production-сборка проходят. Vite сообщает существующие предупреждения о sourcemap UI-компонентов и размере общего пакета.

| Сценарий | Проверка |
|---|---|
| Первый экран без автоматических демонстрационных персонажей | Браузер, проверка запуска |
| Восстановление рисунка и проекта без персонажей | Браузер, тесты сессии и навигации |
| Старые снимки проекта | Существующие тесты валидации и миграций |
| Персонаж, изменение лица, связанный рисунок головы и новый слой | Браузер |
| Предмет без персонажа → создание персонажа → примерка | Браузер, тесты навигации |
| Дерево → независимый скелет → сетка и веса → ключ поворота → воспроизведение | Браузер, регрессии студии |
| Редактор контуров: добавление фигуры и отмена | Браузер, тесты AuthoringPanel |
| Переключение задач, время/клип, Undo/Redo | Браузер, тесты workbench |
| JSON: скачивание и повторное открытие всех объектов | Браузер, тесты сохранения |
| Отказ записи, повтор, ожидание настольной записи, параллельное автосохранение | Тесты projectPersistence и IndexedDB |
| Ошибка SVG, повторный импорт, подложка | Браузер |
| Все шесть форматов экспорта | Браузер; проверено содержимое ZIP: PNG, WebP, кадры PNG, SVG, JSON, JPEG и метаданные |
| Отмена экспорта, ошибка и повтор, повторное скачивание | Браузер для отмены и скачивания; отдельные тесты для ошибки, повтора и гонки отмены |
| F1 для примерки, поиск ответа о розовых участках | Браузер |
| Ширины 1440, 1024, 768 px, выдвижные панели, Tab и видимый фокус | Браузер; ширина страницы совпадает с viewport, без горизонтального переполнения |

Настольная запись проверена через контракт Electron API в автоматических тестах. Упакованное приложение Electron и диалог выбора папки вручную в этой проверке не запускались.

Карты, игровые характеристики, коллизии, модульное строительство и редакторы UI/VFX не добавлялись. Новые и изменённые боевые клипы не создавались; обязательный цикл xray-приёмки из AGENTS.md для таких изменений не требовался.
