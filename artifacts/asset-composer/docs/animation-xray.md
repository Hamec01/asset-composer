# Animation X-Ray

Открыть **Debug → Animation X-Ray**. Режимы действуют только на представление
холста: не меняют проект, палитру персонажа, IK, кости и обычный экспорт.

## Режимы

- **Normal** — исходные тело, одежда и экипировка.
- **Rig Colors** — реальные SVG-силуэты анатомических деталей: L arm красная,
  R arm зелёная, L leg оранжевая, R leg синяя, torso почти чёрный,
  pelvis фиолетовый, head/neck серые. Кисти и стопы светлее своей конечности.
- **Depth Colors** — реальные силуэты в цветах разрешённых `renderDepth.slot`.
  Легенда слоёв доступна в Debug и на контрольных листах.
- **Skeleton** — полный скелет, включая ноги, поверх приглушённых силуэтов.

Цвета постоянны и определены в `src/lib/animationXRay.ts`; версия палитры
попадает в review JSON. L/R — анатомические стороны, они не переименовываются
при смене направления. Для профильного рига RIGHT: near=L, far=R;
LEFT: near=R, far=L.

**Depth shading** в Rig Colors включён по умолчанию. FAR_BACK/FAR_LIMB/BODY_BACK
затемняются на 48%, CROSS_BODY/BODY сохраняют базовый цвет,
NEAR_LIMB/BODY_FRONT/HAND_FRONT/EQUIPMENT_FRONT осветляются на 22%.
Каждый сегмент использует свой фактический слой; far forearm в CROSS_BODY
не затемняется вслед за far upper arm в FAR_LIMB. Неизвестная глубина
не угадывается по координатам или названию стороны. В Depth Colors она серая.

Одежда, волосы и декоративные накладки скрываются, а тело под ними восстанавливается
из тех же деталей и пользовательских замен, которые использует редактор.
**Show equipment** возвращает оружие и щит в обычных цветах. Их изображения можно
скрывать без изменения экипировки, влияющей на позу и хват.

Маркеры **SL/EL/HL** и **SR/ER/HR** обозначают shoulder/elbow/hand.
**N/F** у плеча обозначает near/far. Debug также показывает координаты обоих
плеч и расстояние в единицах рига. Маркеры рисуются поверх тела; сами сегменты
сохраняют фактическое перекрытие корпусом. Монолитные изображения без
полного раздельного тела показывают сообщение о неподдерживаемом режиме.

## Экспорт и маркеры фаз

**Debug → Export Animation Review** открывает список контрольных поз.
Встроенный двуручный удар содержит Guard=0, Windup=280, Apex=600, Contact=880,
Follow-through=1060, Recover=1600 мс. Старые и пользовательские клипы без
маркеров получают шесть равномерных выборок с подписями времени.

`AnimationClip.reviewMarkers?: { label: string; timeMs: number }[]` сохраняется
в проекте. В окне можно менять подписи/время, добавлять и удалять точки.
**Save markers to clip** явно сохраняет список с поддержкой undo/redo;
скачивание само по себе его не сохраняет. Время должно быть конечным и лежать
между 0 и durationMs включительно; подпись не может быть пустой.

ZIP содержит `review-right.svg/png`, `review-left.svg/png`, `review.json`.
В каждом листе четыре колонки NORMAL / RIG COLORS / DEPTH COLORS / SKELETON
и одна строка на контрольную позу. Обе стороны и все колонки используют одну
камеру. NORMAL сохраняет текущий внешний вид. Rig Colors всегда кодирует
глубину яркостью. Оружие и подписи следуют настройкам X-Ray.

JSON содержит времена, направления, камеру, настройки и палитры, все суставы,
плечевые корни и расстояние, исходный порядок одетых визуалов и порядок деталей
анатомии, их привязки, матрицы, bounds, глубину и существующие предупреждения
о длинах/хвате/движении рук, зазоре головы и слоях. Порядок и цвета показывают
фактическое состояние; без отдельного ожидаемого состояния они не доказывают
правильность анимации. Число shoulder distance не имеет произвольного pass/fail.

## Общий генератор

`buildAnimationReview(input)` — общий генератор SVG и JSON без store, DOM и записи
файлов. Он принимает entity, template, clips, clip, items, fitProfiles и опциональные
markers/options. `animationReviewArchive(review, pngRenderer?)` добавляет PNG и ZIP;
по умолчанию PNG рисуется в браузерном Canvas2D, для Node/CI можно передать
растеризатор `(svg, width, height) => Promise<Uint8Array>`.

Опциональные тесты меча и лука используют этот же генератор:

```powershell
$env:SWORD_REVIEW='E:/vectoreditor/output/animation-xray-sword'
$env:BOW_REVIEW='E:/vectoreditor/output/animation-xray-bow.svg'
pnpm --filter @workspace/asset-composer exec vitest run tests/twoHandedSword.test.ts tests/bowVisualReview.test.ts
```

Каталог назначения должен существовать. Для меча создаются `-right.svg`,
`-left.svg`, `-review.json`; для лука — `-xray-right.svg`, `-xray-left.svg`,
`-xray-review.json` в дополнение к обычному художественному листу.
Обычный запуск тестов не пишет контрольные картинки.

## Обязательная приёмка боевых анимаций

Для каждой новой или изменённой боевой анимации:

1. Задать контрольные фазы и сгенерировать review для RIGHT и LEFT.
2. **Rig Colors:** проверить принадлежность деталей, отдельные корни плеч,
   видимое происхождение верхних рук и непрерывность конечностей.
3. **Depth Review:** сверить фактические слои с ожидаемыми по фазам;
   проверить плечо, предплечье, кисть и экипировку независимо.
4. **Skeleton Review:** проверить анатомию, корни, длины, IK и зеркальную проекцию.
5. **Normal Art Review:** проверить одетый силуэт, оружие и результат в рабочем размере.
6. **Accept:** приложить оба контрольных листа и JSON, выполнить регрессии IK,
   глубины и экспорта, typecheck и build.

Зелёные математические тесты не заменяют визуальную проверку. При найденной
ошибке вернуться к её источнику, обновить review и повторить этапы.
Редактор не блокирует сохранение и обычный экспорт.
