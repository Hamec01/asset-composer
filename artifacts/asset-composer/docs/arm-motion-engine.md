# Arm Motion Engine

## Причина

Проверка кода не подтвердила независимый lerp мирового положения локтя.
Движок интерполировал локальные tx/ty, rotation и scale, выполнял FK,
затем IK. Проблемы были в другом:

- Длины IK-цепочки измерялись по уже анимированной FK-позе. Масштаб
  плеча/предплечья и наследуемый масштаб корпуса могли менять длину руки.
- Обычный lerp угла мог вести сустав через длинную дугу при переходе через 180°.
- Кисть и её точка хвата не были отдельным контрактом IK.
- При возврате после выстрела цель кисти проходила возле внутренней границы
  достижимости около плеча. Это вызывало большой поворот локтя даже без растяжения.

## Общий Контракт

`evaluateSkeleton` нормализует именованные цепочки shoulder/elbow/hand L/R:
анимация задаёт вращение, но не длину сегментов. Длины определяет restPose рига,
с учётом морфологии. Дочерние анимированные tx/ty и scale рук не применяются;
масштаб и shear корпуса не наследуются ориентацией сегментов рук.
Изменение самого restPose по-прежнему меняет риг.

Пользовательские цепочки с другими именами включают этот контракт через
`ik.fixedLength: true`. Старые не-arm цепочки сохраняют поддержку stretch.
Один расчёт используется в редакторе, предпросмотре и экспорте.

IK — двухзвенный, с фиксированной ветвью bend или pole. Ветка выбирается
детерминированно относительно опорного ключа, а не прошлого проигранного кадра.
Явные ключи bend разрешают смену стороны. Невозможная цель не удлиняет руку:
кисть остаётся на границе достижимости, Debug показывает ошибку цели.

`ik.gripSocket` задаёт смещение и ориентацию контакта в координатах кисти.
Цель адресует этот контакт, а solver вычисляет положение запястья.
Если поля нет, сохраняется совместимость: цель адресует запястье.
`BonePart.gripSocket` поддерживается креплением предметов и тетивой;
старое поле `grip` остаётся fallback.

`gripObjects` содержит позы виртуального предмета и именованные сокеты.
Несколько IK-цепочек могут ссылаться на один предмет через objectId/socketId.
Этот объект не требует PNG или экипированного предмета: поза рук сохраняется
при экспорте без оружия. Это инфраструктура для двухручного хвата, а не
готовые анимации всех видов оружия или новый визуальный редактор сокетов.

Углы интерполируются по короткой дуге. Для намеренных оборотов есть
`KeyframeTrack.rotationMode: "unwrapped"`; переходы на 360° и больше без
явного режима сохраняют полные обороты. IK-ключи поддерживают smooth easing.
Отражение влево применяется после одного канонического решения IK.

## Debug

На холсте: Debug → Skeleton. Доступны суставы, локальные оси рук,
точки хвата, цели IK, pole, подписи суставов, onion skin N±1/N±2 и
траектории локтей/запястий. L — голубой, R — розовый.
Панель показывает длины, процент ошибки, расстояние до цели,
перемещение суставов, изменение угла и знак изгиба.
Предупреждения: длина >1%, цель >2 единиц при mix=1, поворот >45°,
шаг >10 единиц, неявная смена ветви.
Кнопка загрузки экспортирует JSON по всем кадрам и полукадрам клипа.
Числа указаны в исходных координатах спрайта, не в увеличенных экранных пикселях.

## Лучник И Проверки

Сохранены 2000 мс / 24 fps / 48 кадров. Вместо 101 ключа рук оставлены
16 опорных состояний, включая заднюю дугу локтя, удержания и переход IK/FK в конце.
Подъём → захват → натяг → удержание → отпускание → возврат.
Возврат кисти проходит над плечом, не через его внутреннюю окружность.
Новые рисунки в этом проходе не создавались. Полёт стрелы остаётся отдельной задачей.

Автотест проверяет 97 отсчётов в каждом направлении: кадры и полукадры,
ошибку длины <1%, попадание активной IK-цели <2 единиц, отсутствие
неявного flip, поворотов >45° и скачков >10 единиц за полукадр.
Общие тесты также проверяют FK, масштаб корпуса, пользовательский риг,
неосевые сегменты, разные grip socket, совместный движущийся предмет,
недостижимые цели, зеркалирование и сохранение полей через JSON-схему.
